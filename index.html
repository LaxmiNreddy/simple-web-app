2. Docker Desktop Setup

Docker Desktop provides a convenient local environment for running containers and, when Kubernetes is enabled, a local Kubernetes cluster.

Install Docker Desktop

Download Docker Desktop from the official Docker website:

Docker Desktop

After installation

  1. Start Docker Desktop.
  2. Wait until Docker Desktop reports that Docker is running.
  3. Open Docker Desktop settings.
  4. Open the Kubernetes section.
  5. Enable/create the local Kubernetes cluster.
  6. Wait until Kubernetes becomes ready.

Verify Docker

docker version
docker info
docker ps

What does docker ps show?

It shows the containers currently running through Docker.

3. Kubernetes Setup

Kubernetes is responsible for managing application workloads. Docker Desktop can provide a local Kubernetes cluster for development.

Check kubectl

kubectl version --client

Check Kubernetes context

kubectl config get-contexts

Check current context

kubectl config current-context

If Docker Desktop's Kubernetes context is available, it is commonly named: 

docker-desktop

You can select it with:

kubectl config use-context docker-desktop

Check Kubernetes cluster

kubectl cluster-info

Check nodes

kubectl get nodes

The node should normally show: 

STATUS
Ready

4. Important Kubernetes Components

Component Meaning
Cluster The complete Kubernetes environment.
Node Machine/environment where workloads run.
Namespace Logical separation of Kubernetes resources.
Pod Smallest deployable Kubernetes unit.
Deployment Maintains application Pods and their desired state.
Service Provides stable networking to Pods.
ConfigMap Stores non-sensitive configuration.
Secret Stores sensitive configuration data.
Ingress Routes external HTTP/HTTPS traffic to services.

Basic Kubernetes Commands

5. Argo CD Setup

Argo CD is a GitOps continuous delivery tool for Kubernetes.

Step 1 — Create Argo CD Namespace

kubectl create namespace argocd

Step 2 — Install Argo CD

This is the command you started with: 

kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

Step 3 — Check Argo CD Pods

kubectl get pods -n argocd

Wait until the required Pods become ready.

Step 4 — Check all Argo CD resources

kubectl get all -n argocd

Step 5 — Check Services

kubectl get svc -n argocd

Step 6 — Check Deployments

kubectl get deployments -n argocd

Step 7 — Check Pods

kubectl get pods -n argocd

6. Argo CD Components

argocd-server

Provides the Argo CD API server and Web UI.

argocd-repo-server

Connects to repositories and renders application manifests.

argocd-application-controller

Compares desired state with the live Kubernetes state and performs reconciliation.

argocd-redis

Provides caching support for Argo CD.

argocd-dex-server

Used for authentication and identity integrations where configured.

ApplicationSet Controller

Helps generate and manage multiple Argo CD Applications.

7. Get Argo CD Admin Password

The initial installation creates an initial admin Secret.

PowerShell / Linux-style command

kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}"

The value is Base64 encoded.

Linux/macOS decoding

kubectl -n argocd get secret argocd-initial-admin-secret \
-o jsonpath="{.data.password}" | base64 -d

Username: 

admin

8. Open Argo CD Web UI

For a local setup, the easiest way to access Argo CD is port forwarding. 

kubectl port-forward svc/argocd-server -n argocd 8080:443

Then open: 

https://localhost:8080
Your browser may show a certificate warning because the local Argo CD server commonly uses a self-signed certificate.

9. Argo CD CLI

Check CLI

argocd version

Login

argocd login localhost:8080 --username admin --insecure

List Applications

argocd app list

Get Application

argocd app get guestbook

Synchronize Application

argocd app sync guestbook

10. GitOps — How Argo CD Works

The most important concept to understand is the difference between desired state and live state.

Concept Meaning
Desired State Configuration stored in Git.
Live State What currently exists in Kubernetes.
Synced Desired state and live state match.
OutOfSync They are different.
Healthy Application resources are considered healthy.
Degraded One or more resources have health problems.

GitOps Flow

Developer changes YAML
→
Git commit
→
Git push
→
Argo CD detects change
→
Kubernetes updated

11. Example Argo CD Application

Create a file called: 

application.yaml

Example:

apiVersion: argoproj.io/v1alpha1
kind: Application

metadata:
  name: guestbook
  namespace: argocd

spec:

  project: default

  source:
    repoURL: https://github.com/argoproj/argocd-example-apps.git
    targetRevision: HEAD
    path: guestbook

  destination:
    server: https://kubernetes.default.svc
    namespace: guestbook

  syncPolicy:
    automated:
      prune: true
      selfHeal: true

Apply Application

kubectl apply -n argocd -f application.yaml

Check Application

kubectl get applications -n argocd
kubectl get application guestbook -n argocd

14. Troubleshooting

Problem: Kubernetes is not running

kubectl get nodes

If the command cannot connect to the cluster, check Docker Desktop and Kubernetes settings.

Problem: Wrong Kubernetes context

kubectl config get-contexts
kubectl config current-context

Select the correct context if required: 

kubectl config use-context docker-desktop

Problem: Argo CD Pods are not running

kubectl get pods -n argocd

Then:

kubectl describe pod <pod-name> -n argocd

And:

kubectl logs <pod-name> -n argocd

Check events

kubectl get events -n argocd --sort-by=.lastTimestamp

Problem: Port 8080 already used

Use another local port: 

kubectl port-forward svc/argocd-server -n argocd 8090:443

Then open: 

https://localhost:8090

Check Argo CD service

kubectl get svc argocd-server -n argocd

15. Local vs Production

Local Development Production
Docker Desktop Kubernetes Enterprise / managed Kubernetes cluster
Port forwarding Ingress / Load Balancer
Simple local configuration Enterprise security configuration
Non-HA Argo CD can be used for learning/testing HA architecture should be considered
Local Git repository Enterprise Git repository
Local credentials RBAC / SSO / controlled secrets
Important: A local Docker Desktop + Argo CD setup should not simply be copied into production. Production environments require appropriate security, RBAC, availability, monitoring, networking, credentials, backup and upgrade strategies.

16. Docker vs Kubernetes vs Argo CD

Technology Main Responsibility
Docker Builds and runs containers.
Kubernetes Manages application workloads and containers.
Git Stores desired application/deployment configuration.
Argo CD Synchronizes Kubernetes with Git.

Simple Example

Imagine your application is a Java Spring Boot service.

Spring Boot JAR
→
Docker Image
→
Kubernetes Pod
→
Kubernetes Service

Argo CD is responsible for ensuring that the Kubernetes resources defined in Git are actually deployed in the cluster.
